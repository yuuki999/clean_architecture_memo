# Laravelの使い方
今後0からプロジェクトをlaravelで構築することも考慮して、自分なりの理解を改めてまとめておく。

## Laravel アーキテクチャの主要コンポーネント
1. Controller: 
   - HTTPリクエストを受け取り、適切な処理を行い、レスポンスを返す。
   - ビジネスロジックを直接含まず、ServiceやModelを利用して処理を行う。

2. Model:
   - データベーステーブルとのマッピングを行う。
   - データに関するビジネスロジックを含む（バリデーション、リレーションシップなど）。

3. View:
   - ユーザーに表示するHTMLを生成する。
   - Bladeテンプレートエンジンを使用。

4. Service:
   - 複雑なビジネスロジックをカプセル化する。
   - Controllerから切り出された処理を含む。
   - 複数のModelを操作する処理や、外部APIとの連携などを行う。

5. Repository:
   - データの永続化層とアプリケーションロジックを分離する。
   - データベース操作をカプセル化し、Modelの使用を抽象化する。

6. Middleware:
   - HTTPリクエストをフィルタリングし、前処理や後処理を行う。
   - 認証、CSRF保護、ログなどの横断的な関心事を処理する。

7. Provider:
   - アプリケーションの起動時に、サービスの登録やブートストラップを行う。
   - 依存性注入コンテナにサービスを登録する。

8. Factory:
   - テスト用のモックデータを生成する。
   - データベースシーディングにも使用される。

9. Policy:
   - 認可ロジックを定義する。
   - 特定のモデルに対する操作権限を制御する。

10. Event & Listener:
    - イベント駆動型プログラミングを実現する。
    - アプリケーション内の疎結合なイベント処理を可能にする。

11. Job & Queue:
    - 時間のかかる処理を非同期で実行する。
    - バックグラウンドでのタスク処理を可能にする。


インターフェイスは過剰実装になってしまう可能性もあるので、慎重に検討する。
